Executive Summary & Problem Formulation

Understanding the socioeconomic and technological problem context that inspired this project.

The Ground Reality

Problem Statement

India produces over 1.5 million ITI & Polytechnic graduates annually across essential trades such as Welder, Electrician, and Fitter. However, this demographic faces acute structural unemployment:

  • Information Asymmetry: Generic job portals (LinkedIn, Naukri) cater to corporate/IT white-collar jobs and fail to index technical vocational skill taxonomies (e.g., MIG vs TIG welding, PLC troubleshooting).
  • Local Mobility Barriers: Vocational technicians require jobs in localized manufacturing clusters (e.g., Chakan, Peenya, Ambattur, Manesar).
  • Lack of Apprenticeship Awareness: Millions miss government stipend schemes (NAPS, PMKVY, PM Vishwakarma) due to fragmented portals.
The Engineered Solution

SkillMatch Platform Objectives

SkillMatch is an AI-powered, full-stack vocational matching ecosystem engineered specifically for technical candidates:

  • Granular Skill-to-Job Matching: Natural Language Processing (TF-IDF + Cosine Similarity) coupled with multi-factor weighting to rank hyper-local manufacturing vacancies.
  • Explainable AI (XAI): Provides candidates with exact reasons for compatibility and pinpoints missing technical competencies.
  • Integrated Government Ecosystem: Direct links to verified NAPS apprenticeships and MSDE government schemes to bridge skill gaps.
  • Salary Transparency: Machine Learning regression model predicting fair market wage benchmarks based on experience and city tier.

Why Decoupled FastAPI + React?
Decoupling allows the heavy Python mathematical and scikit-learn models to execute natively on the server without blocking UI threads. FastAPI's asynchronous architecture (ASGI) can process concurrent recommendation requests while the React frontend remains silky smooth.

The AI / Machine Learning Engine

SkillMatch avoids simple keyword matching by implementing five synchronized Machine Learning algorithms in app/ml/.

Algorithm 1 — Core Matching

Multi-Factor Weighted Fit Formula

A candidate’s final job suitability score is not determined by skills alone. It synthesizes five dimensional vectors based on industrial hiring weights:

Mathematical Formula (Normalized [0, 100])
Final Score = (0.50 × Skill_Match) + (0.20 × Trade_Match) + (0.15 × Location_Match) + (0.10 × Experience_Match) + (0.05 × Salary_Match)
Component Weight Breakdown:
  • Skill Match (50%): Blends exact set-overlap (60%) with TF-IDF cosine similarity (40%) of trade descriptions.
  • Trade Match (20%): Strict trade code parity (100% for Welder==Welder, 20% penalty for trade mismatch).
  • Location Match (15%): 100% for city cluster match; 70% for state match; 40% for cross-state.
  • Experience Match (10%): Evaluates student years against [exp_min, exp_max] with a penalty slope for deficits.
  • Salary Match (5%): Evaluates candidate expectation against employer budget envelope.
Explainable AI Output (XAI):

Rather than presenting a black-box percentage, the engine returns human-readable justification strings:

✓ Direct trade match (ITI Welder)
✓ Matched 4 skills: MIG, TIG, Blueprint, Arc
✓ Preferred location (Pune Industrial Hub)
✓ Experience requirements fully satisfied
Algorithm 2 — Natural Language Processing

TF-IDF Vectorization & Cosine Distance

To account for semantic similarities in technical terminology, text descriptions of candidate skills and job responsibilities are vectorized into an n-dimensional vector space:

Term Frequency–Inverse Document Frequency (TF-IDF) & Cosine Metric
TF-IDF(t, d, D) = TF(t, d) × log( |D| / (1 + |{d ∈ D : t ∈ d}|) )

Cosine_Similarity(U, V) = ( U · V ) / ( ||U|| ||V|| ) = ∑(Ui × Vi) / ( √(∑ Ui²) × √(∑ Vi²) )

Implemented via sklearn.feature_extraction.text.TfidfVectorizer(stop_words='english'). This handles trade synonym variations and weights rare technical competencies (e.g., "Radiographic Testing") higher than ubiquitous terms.

Algorithm 3

KNN Job Recommender

Model: NearestNeighbors(n_neighbors=5, metric='cosine')

Constructs a normalized 39-dimensional feature vector for every job:

  • Trade One-Hot Vector (3 dims)
  • Normalized Experience (1 dim)
  • Normalized Salary (1 dim)
  • Multi-Hot Skill Vector (34+ dims)

Finds the closest "Jobs Like This" when a candidate browses any specific opening.

Algorithm 4

Ridge Salary Predictor

Model: Ridge(alpha=1.0) with L2 regularization.

Trained on 600 synthetic manufacturing market benchmark points across Indian industrial zones:

Loss = ||y - Xw||² + α||w||²

Takes trade, experience, tier-1 city flag, verified skill count, and polytechnic diploma flag to predict a fair monthly wage range (e.g., ₹18,000 – ₹24,500).

Algorithm 5

K-Means Job Clustering

Model: KMeans(n_clusters=4, random_state=42)

Unsupervised clustering on the TF-IDF matrix of all active job titles, trades, and skill requirements.

Automatically categorizes vacancies into macroeconomic industrial clusters (Heavy Fabrication, Automation, Precision Assembly, Hydraulics) for admin analytics.

Database Architecture & Data Model

The database consists of 11 normalized relational tables implemented using SQLAlchemy 2.0 ORM with strict Foreign Key integrity and cascading deletions.

Table Name Primary Key Foreign Keys & Relationships Key Attributes & Constraints
users id (Int) 1:1 with student_profiles; 1:N with applications email (Unique), hashed_password, role ('student' | 'admin')
trades id (Int) 1:N with skills, jobs, student_profiles code ('welder'|'electrician'|'fitter'), name, icon
skills id (Int) N:1 with trades.id (CASCADE) name (Indexed), category (e.g., Fabrication, Wiring)
student_profiles id (Int) N:1 with users.id, N:1 with trades.id qualification, experience_years, preferred_location, expected_salary_min
student_skills id (Int) N:1 with student_profiles.id, N:1 with skills.id proficiency_level ('Beginner'|'Intermediate'|'Expert')
companies id (Int) 1:N with jobs, 1:N with apprenticeships name, industry, city, is_verified (Bool)
jobs id (Int) N:1 with companies.id, N:1 with trades.id title, salary_min/max, experience_min/max, city, status
job_skills id (Int) N:1 with jobs.id, N:1 with skills.id Association table mapping required competencies to job postings
applications id (Int) N:1 with users.id, N:1 with jobs.id status ('Applied'|'Under Review'|'Shortlisted'|'Selected'), applied_at
government_schemes id (Int) N:M with trades via scheme_trades name, category, eligibility_criteria, benefits, official_website
institutes id (Int) Independent entity name, city, placement_rating, placement_officer_phone

RESTful API Contract & Endpoints

All endpoints are prefixed under /api/v1/ with strict Pydantic schema validation for request inputs and response serializers.

HTTP Method Endpoint URI Auth / Role Description & Computational Action

POST /api/v1/auth/login Public OAuth2 password request form; verifies credentials and returns bearer token.
GET /api/v1/auth/me Bearer JWT Fetches authenticated user identity, role, profile details, and selected skills.
GET /api/v1/jobs Public Paginated job search supporting query parameters: trade, location, salary_min. Automatically injects match scores if user is authenticated.

POST /api/v1/matching/knn-recommend Optional JWT Uses K-Nearest Neighbors to find similar jobs based on 39-dim cosine feature vector.
POST /api/v1/matching/skill-gap Public Computes technical readiness score for a targeted job, identifying matched vs missing skills, and dynamically connects missing skills to relevant government training schemes.
POST /api/v1/matching/predict-salary Public Runs Ridge Regression model to estimate realistic wage envelope based on trade, city tier, experience, and skill count.
GET /api/v1/student/dashboard Bearer (Student) Aggregates recommendations, submitted applications, and saved jobs in a single call.
POST /api/v1/student/apply/{job_id} Bearer (Student) Submits job application with optional cover note and records timestamp.
GET /api/v1/analytics/overview Bearer (Admin) Calculates platform KPIs, trade distributions, and executes K-Means clustering over all active vacancies.

Operational Workflow & Candidate Journey

How a vocational student interacts with the system from onboarding to secured employment or government upskilling.

Step 1: Rapid 2-Step Onboarding

The student registers with their phone number/email, specifies their ITI trade (Welder, Electrician, or Fitter), their home industrial cluster (e.g., Pune Chakan), and expected wage.

Step 2: Technical Skill Tagging

The student selects verified proficiencies from our curated taxonomy (e.g., TIG Welding, Blueprint Reading, Lathe Turning) and rates their experience level.

Step 3: Real-Time Vector Ranking (AI Engine Execution)

FastAPI invokes MatchingEngine.calculate_match(). The student's dashboard renders vacancies ordered by overall fit score with transparent score bars (Trade 20%, Skill 50%, Location 15%, etc.).

Step 4: Skill Gap Analysis & Scheme Redirection

If a candidate has a 75% match on a high-paying job, the system highlights the missing 25% (e.g., "Radiographic Testing") and provides one-click redirection to an active, free PMKVY or NAPS training course teaching that exact skill.

Step 5: Direct Employer Application & WhatsApp Connect

Candidates apply directly through the portal with tracked statuses (Applied → Under Review → Shortlisted). They can also reach institute placement officers directly on WhatsApp without intermediary brokers.

Viva Voce / Examiner Defense Q&A

Frequently asked questions during technical defenses, external college viva, and project evaluations.

Q1 Why did you use TF-IDF + Cosine Similarity instead of simple SQL LIKE '%skill%' queries?
SQL LIKE or set-intersection is binary (either matched or not) and fails to capture term frequency or importance. TF-IDF penalizes common filler words while giving higher mathematical weight to rare technical specialties (like "MIG" or "PLC"). Cosine similarity maps candidates and jobs to a normalized geometric angle between 0 and 1, allowing fuzzy semantic ranking rather than rigid boolean filtering.
Q2 Why choose Ridge Regression over Ordinary Least Squares (OLS) Linear Regression for salary estimation?
Our training data in salary_predictor.py contains correlated features (e.g., experience years and verified skill counts often rise together, causing multicollinearity). Standard linear regression tends to produce unstable, high-variance coefficient estimates when features are collinear. Ridge Regression applies an L2 penalty (α||w||²) which shrinks the weights, prevents overfitting, and produced a higher test R² score and lower Mean Absolute Error (MAE).
Q3 How does the system ensure data security and prevent unauthorized access to administrative features?
We implemented role-based access control (RBAC) via FastAPI dependency injection (get_current_active_admin). Passwords are never stored in plaintext; they are hashed with salted Bcrypt. Protected endpoints inspect the cryptographically signed JWT token header. If a regular student token attempts to call POST /api/v1/jobs or access admin analytics, FastAPI raises an HTTP 403 Forbidden exception before any controller logic executes.
Q4 How scalable is this architecture if deployed to production?
The backend is completely stateless because session authentication relies on JWT tokens rather than in-memory server sessions. The FastAPI server can be scaled horizontally behind an Nginx reverse proxy across multiple Uvicorn worker processes or Docker containers. For production, the database engine URL in config.py can be changed from SQLite to PostgreSQL with a single connection string without modifying any SQLAlchemy models.
